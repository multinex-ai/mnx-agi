# Living realm and documentation board (2026-11-14)
Maintain realm.md as the project entry point with explicit Vision, Status, Abstract, owner, scope, stable realm ID, module graph, evidence and next action. Keep business capabilities, software modules, tasks and documents distinct with typed relationships. Application documentation includes frontend, backend and infrastructure clusters, expandable subtopics, PRD, board and state; Markdown/frontmatter and stable IDs support Obsidian navigation.
After each progress-bearing turn, update authoritative project state, changed source documents, evidence and the single generated offline HTML report. Explain with purpose-selected visuals, actual UI previews or labelled concepts, exploded views and useful analogies; preserve project branding and accessible text equivalents. Follow the purpose-led visual standard, not diagram quotas.
Persist the authorized root composite and exact document graph in verified realm-scoped MemQ plan state when available. Version snapshots with parent hashes, full source content, typed edges and asset manifests; verify readback. A catalog or asset path alone cannot recreate missing bytes. Mark graph/text restoration separately from full visual restoration. Use conditional revisions where supported, record pending local synchronization on failure, and never claim an installed universal turn hook, live Mars service or full restore without evidence.
Authorize realm scope before discovery, search or slicing. Use bounded typed traversal and exact adjacency/BFS as the measured baseline. Treat semantic ANN search separately from exact dependency traversal. Adopt newer graph/index/compression algorithms only with primary-source research and reproducible correctness, latency, memory and update-cost benchmarks on representative workloads. Hash integrity is not authorization. Cross-realm edges never grant access.
This local guidance does not grant external publication, paid resources, cross-realm disclosure or extra agent permissions. Package publication and other clients' runtime adoption require separate verification.
