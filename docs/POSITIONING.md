# MNX-AGI positioning

## Product identity

**MNX-AGI — Recursive Agent Harness + MemQ**

**Across agents. Across sessions. Compounding knowledge.**

MNX-AGI is reusable agent infrastructure: a model-agnostic Recursive Agent Harness paired with MemQ for persistent memory. It helps supported agents plan, act, verify, remember, and improve—carrying useful context across sessions and turning verified work into reusable knowledge.

## GitHub description

MNX-AGI + MemQ: a model-agnostic Recursive Agent Harness that helps agents remember, resume, and build on verified work, with persistent memory and universal vector-translation interfaces for supported embeddings.

## Short copy

Bring your models. Connect your tools. Build on what your agents learn.

MNX-AGI guides the work. MemQ carries the knowledge forward. Together, they are designed for seamless continuity across compatible agents, with explicit project boundaries and evidence-based learning.

Switch models. Keep the context. Build on what works.

## Explain the benefit before the mechanism

| Mechanism | User-facing benefit |
|---|---|
| Persistent memory | Spend less time repeating the brief and more time moving the work forward |
| Portable harness and scoped handoffs | Carry approved context into the next supported agent, tool, or session |
| Verified learning loop | Keep a useful fix or decision available for the next task |
| Universal vector-translation interfaces | Evaluate supported embedding formats within a common memory workflow as the model stack evolves |
| Source and checkpoint provenance | See why a decision was made and where the next agent should resume |

Use “universal vector translation” with its [compatibility definition](VECTOR_TRANSLATION.md). Dimension conversion alone does not establish semantic equivalence between embedding models. The customer promise is portable, reusable knowledge with verified compatibility, not lossless conversion between every model.

## Reusable infrastructure thesis

Package the capabilities that help existing agent systems: a repeatable work cycle, scoped memory, recoverable progress, bounded handoffs, and evidence-based evaluation. Offer a practical adoption path within existing hosts and workflows. Teams can adopt the harness and connect MemQ without adopting a custom operating system or desktop.

The product's value proposition is coordinated work that retains context. An authorized agent can build on another agent's verified findings; a later session can resume from an evidenced checkpoint; a useful procedure can be refined after independent reuse. Each step depends on the actual host integration and account permissions.

Typed event delivery, hardware-aware resource selection, execution scheduling, model circuit breakers, and autonomous opportunity discovery are separate potential modules. Describe them as shipped only after source review, integration, and acceptance evidence. See the [module boundary guide](HARNESS_MODULES.md).

## Wording and claim boundaries

Use “Recursive Agent Harness” for the bounded loop of recall, action, verification, checkpointing, learning, and evaluated refinement. Describe compounding as the reuse and improvement of retained knowledge. Describe broad model support as an architectural property; identify configured host support separately.

Do not describe an unconfigured app as connected, a shared namespace as a permission grant, a plan record as a lock, or the experimental gateway as system-wide enforcement. Do not claim universal compatibility, flawless memory, autonomous self-modification, model training, or measured performance gains without the matching evidence.

## Evidence for differentiation

Lead with the combination of portable operating guidance, scoped persistent memory, verifiable continuity, and reviewed learning. Frameworks can be complementary integration targets. [LangChain documents routing, handoffs, skills, and custom workflows](https://docs.langchain.com/oss/python/langchain/multi-agent); [CrewAI documents configurable language-model providers](https://docs.crewai.com/en/concepts/llms). Distinguish MNX-AGI through its documented workflow and measured integration outcomes rather than claiming these ecosystems lack coordination or model choice.

Use original product copy. Market-size forecasts, acquisition narratives, competitor inferiority, performance rankings, and revenue predictions require their own current primary evidence before publication. No vendor endorsement or integration is implied by architectural comparison.
